# Blog Pipeline (SEO competitor analysis -> new blog post)

Takes a competitor article URL and a target title, analyses what that article covers and what it misses,
writes a new original post with an LLM, validates it, and drops it into your existing blog template.
Only the content slots change. Everything else in the template (header, footer, hero image block,
Also Read, CTA, scripts) stays byte-for-byte the same.

## What it does

1. **fetch**: downloads ONLY the one URL you give it, strips hidden/script content, saves clean text.
2. **You read it and approve it** (human gate, so an empty or blocked page never reaches the LLM).
3. **generate**: LLM call 1 builds the keyword/gap/outline strategy. LLM call 2 writes the article as JSON.
   The validator checks it (retries up to 3 times with the errors fed back). The renderer injects it into the template.
4. You review `review.md`, check the facts, and publish.

The LLM never writes HTML. It outputs JSON, and the code builds the HTML. Section ids and TOC links
are generated by the same function, so they always match.

## Setup (once)

Requires Node 18.3+ (you have 22).

```
npm install
```

Create a file named exactly `.env` in this folder:

```
OPENROUTER_API_KEY=sk-or-...
OPENROUTER_MODEL=google/gemini-3-flash-preview
MAX_TOKENS=12000
```

Make sure `run.js` loads it (first line of `run.js`):

```js
try { process.loadEnvFile(); } catch {}
```

Convert your existing blog page into the template (one time):

1. Save your current published post as `original.html` in this folder.
2. Run:

```
node make-template.js original.html template.html
```

It replaces only the content slots with `{{PLACEHOLDERS}}` and aborts loudly if any anchor does not match exactly once.

Fill in `fact-sheet.md` with product features you can personally confirm. The writer may claim nothing
about Hitech BillSoft beyond what is listed there.

## Making a post

```
node run.js fetch --title "Place of Supply Errors in GST Billing" --url https://www.gimbooks.com/blog/place-of-supply-errors-gst-billing/
```

Note the slug it prints (built from the title, e.g. `place-of-supply-errors-in-gst-billing`). The slug becomes the live URL
(`/blogs/<slug>/`). To choose your own, add `--slug your-slug` to the fetch command.

Open `work/<slug>/source.txt` and check it is the full article. If the preview says
"LOOKS EMPTY OR BLOCKED", do not approve. Paste the article text into a `.txt` file and run:

```
node run.js fetch --title "..." --slug <slug> --file pasted.txt
```

When the source looks right:

```
node run.js approve  --slug <slug>
node run.js generate --slug <slug>
```

Approval is tied to a hash of the exact text. If you edit `source.txt` afterwards, run `approve` again.

## Outputs

| Path | What it is |
|---|---|
| `out/blogs/<slug>/index.html` | The finished draft, ready to copy into your site repo |
| `work/<slug>/review.md` | Warnings, overlap %, and the checklist of facts to verify |
| `work/<slug>/strategy.json` | Keywords, gaps and outline the LLM planned from |
| `work/<slug>/article.json` | The raw article JSON |
| `work/<slug>/article.rejected.json` | Only appears if all 3 attempts failed validation |

## Before you publish (do not skip)

1. Work through the `factsToVerify` checklist in `review.md`. GST section numbers, rates, thresholds and dates are where LLMs invent things.
2. Read the draft once for tone and accuracy.
3. Copy `out/blogs/<slug>/` into your site's `blogs/` folder and add the hero/og image at `assets/blogs/<slug>/hero-image.webp`.
4. The hero block is left exactly as in the template, so it still points at the template's original image until you edit that one line.
5. "Also Read", sitemap and any blog listing page are not updated by the pipeline. Do those yourself.
6. Do not publish many posts in a short window with identical structure. Vary them and add real examples.

## What the validator enforces

- JSON shape, section/FAQ counts, title and meta description lengths
- No HTML tags and no links anywhere in model output (also the prompt-injection backstop)
- Unique headings, matching TOC links and heading ids, correct FAQ wiring, one open FAQ panel
- Brand mentions capped, keyword placement checked
- Verbatim overlap with the source: warns at 3%, fails at 8% (7-word phrases)
- The static template text is verified unchanged after rendering
- It refuses to overwrite an existing post unless you pass `--overwrite`

## Optional environment variables

| Variable | Default | Purpose |
|---|---|---|
| `MAX_TOKENS` | 12000 | Output cap per LLM call. Lower it if OpenRouter says you cannot afford the request |
| `SITE_URL` | https://billingsoftwareindia.in | Used for canonical, og:url and og:image |
| `SITE_ROOT` | unset | Path to your site repo; warns if the og:image file is missing |
| `WORK_DIR` / `OUT_DIR` | `work` / `out` | Where working files and drafts go |

## Troubleshooting

| Problem | Fix |
|---|---|
| `Set OPENROUTER_MODEL` | `.env` is not named exactly `.env`, is in the wrong folder, or `loadEnvFile` line is missing. Or run `node --env-file=.env run.js ...` |
| `nothing to approve` / `source not approved` | The slug in your command differs from the one fetch printed. Copy it exactly |
| HTTP 402 from OpenRouter | Add credits, or lower `MAX_TOKENS` |
| `output truncated` | `MAX_TOKENS` is too low for that model. Raise it |
| HTTP 400 mentioning `response_format` | That model does not support JSON mode. Remove the `response_format` line in `gemini.js` |
| `Rejected after 3 attempts` | Read `article.rejected.json`. Usually overlap with the source is too high, or the output contained a link or tag. Re-run, or try a stronger model |
| `anchor "..." matched N times` in make-template | The template page differs from the expected structure. Fix the anchor named in the error |
| Source preview shows few headings or little text | Page is JS-rendered or bot-blocked. Use `--file` with pasted text |

## Files

- `run.js`: the three stages (fetch, approve, generate)
- `prompts.js`: strategy and writer prompts (edit these to change tone, length, structure rules)
- `gemini.js`: the LLM client (currently OpenRouter; the export is still named `gemini`)
- `validate.js`: article and rendered-page checks
- `render.js`: JSON -> HTML using your template's classes
- `make-template.js`: one-time original page -> template converter
- `lib.js`: slugs, escaping, heading-id generation
- `fact-sheet.md`: the only product claims the writer may make
